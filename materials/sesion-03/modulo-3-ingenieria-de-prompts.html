Ingeniería de prompts para crear un MVP real.

De pedir respuestas a diseñar instrucciones útiles, evaluables y accionables para prototipos con IA.

Meta del módulo: terminar con un prompt maestro y un prototipo conceptual capaz de explicar qué hace, para quién, con qué datos y cómo se evalúa.
Punto de partida

La gran idea

02

Un buen prompt no es una frase bonita: es una instrucción que convierte una idea en una prueba real.

Antes“Hazme una app para estudiar mejor.”
Demasiado amplio, poco medible, sin usuario ni criterio.
Después“Diseña un MVP para estudiantes de 3° medio que recomiende ejercicios según tema, dificultad y error más frecuente.”
Concepto

¿Qué significa que un sistema “aprenda”?

03
1Observa ejemplos
2Encuentra regularidades
3Ajusta una regla interna
4Prueba si acierta

Para prompts: la IA no “entiende” tu intención completa si no le entregas contexto, datos, tarea y criterio.

Mapa mental

Vocabulario mínimo para entender IA

05
EjemploUn caso que la IA observa · una canción escuchada.
VariableDato que describe un caso · energía, duración, género.
ModeloRegla aprendida desde patrones · “Le gustan canciones bailables”.
PredicciónSalida estimada · “Esta canción te gustará”.
Evaluación¿Funcionó? · ¿El usuario hizo clic o no?

Traducción práctica: para crear un MVP, primero decidimos qué entrada recibe, qué salida entrega y cómo sabremos si sirve.

Aplicaciones

Cuatro usos cercanos de IA

06
RecomendarElegir algo probable para ti. Contenido, ejercicio, música.
ClasificarAsignar una categoría. Urgente/no urgente, tema, nivel.
PredecirEstimar un resultado futuro. Riesgo, puntaje, demanda.
Reconocer patronesDetectar formas, hábitos o señales. Rutinas, errores, estilos.

Idea MVP: cada uso puede convertirse en un prototipo con prompts bien diseñados.

IA generativa

Prompt como científico de datos

07
ContextoQué problema estoy analizando.
DatosQué información tengo.
TareaQué necesito que haga.
CriterioCómo evaluar una buena respuesta.
RiesgoQué sesgos o límites debe revisar.
“Actúa como científico de datos. Tengo [contexto] y estos datos: [datos]. Necesito [tarea]. Evalúa tu respuesta con [criterio] y menciona riesgos o sesgos posibles.”

Versión MVP: agrega usuario, flujo de entrada, salida esperada y forma de validar.

Cambio de mentalidad

Del prompt suelto al prompt de producto

08
Prompt sueltoBusca una respuesta rápida, pero suele quedar incompleto, ambiguo y difícil de evaluar.
Prompt de productoDefine usuario, problema, datos, tarea, restricciones, formato y métrica de éxito.
MVP con IAPrueba pequeña, realista y medible para saber si una idea merece seguir creciendo.

No se trata de “hacer todo”. Se trata de probar lo mínimo que demuestra valor.

Método práctico

Anatomía de un prompt para MVP

09
Actúa como [rol experto]. Quiero crear un MVP para [usuario] que resuelva [problema]. Datos disponibles: [campos, ejemplos, supuestos]. Tarea: diseña [flujo / recomendación / clasificación / predicción]. Restricciones: [tiempo, privacidad, tecnología, nivel]. Entrega: [formato exacto]. Criterios de éxito: [métrica o prueba]. Riesgos: identifica sesgos, límites y preguntas faltantes.
Regla de oroOtra persona debe poder probar la idea sin que tú tengas que explicarla de nuevo.
Chequeo rápido¿Quién lo usa? ¿Qué problema resuelve? ¿Qué datos necesita? ¿Qué salida entrega? ¿Cómo sabremos si sirve?
Ejemplo claro

MVP 1: tutor de estudio con IA

10
ProblemaEstudiantes estudian mucho, pero no siempre detectan qué no entienden.
MVPRecibe materia + respuesta y devuelve diagnóstico, pista y ejercicio breve.
ÉxitoEl estudiante entiende su error y mejora en un segundo intento.
“Actúa como tutor de matemática. Lee esta respuesta de un estudiante de enseñanza media. Identifica el error principal, explica una pista sin resolver todo, crea un ejercicio similar y entrega una rúbrica simple de autoevaluación.”
Ejemplo claro

MVP 2: recomendador de hábitos deportivos

11
UsuarioEstudiante que quiere entrenar, pero no sabe qué rutina escoger.
Datos mínimosDeporte, tiempo disponible, experiencia, objetivo, lesión o restricción.
SalidaRutina breve, segura y explicada, con alternativas de baja exigencia.
“Actúa como analista deportivo. Con estos datos del usuario: [deporte, objetivo, minutos, nivel, restricción], recomienda 3 micro-rutinas. Explica por qué elegiste cada una, qué riesgo revisar y cómo medir progreso en 7 días.”

Si hay salud o lesión, el MVP debe recomendar prudencia y no reemplazar a un profesional.

Ejemplo claro

MVP 3: clasificador de solicitudes del curso

12
ProblemaDudas mezcladas: contenido, nota, fecha, entrega o problema técnico.
MVPClasifica mensajes, sugiere prioridad y redacta una respuesta inicial.
ValidaciónComparar IA versus criterio docente en 20 mensajes reales o simulados.
“Clasifica el siguiente mensaje estudiantil en una de estas categorías: contenido, evaluación, plazo, plataforma, personal u otro. Asigna prioridad baja/media/alta, explica la evidencia textual y sugiere una respuesta breve, respetuosa y académica.”
Iteración

Prompting iterativo: 1 → 2 → 3

13
Versión 1“Dame una idea de app con IA.” Resultado: genérico.
Versión 2Agrega usuario, problema y salida. Útil, pero aún difícil de evaluar.
Versión 3Agrega datos, restricciones, métrica y riesgos. Resultado: prototipo con criterio.

La pregunta no es “¿la IA respondió?”. La pregunta es “¿la respuesta sirve para tomar una decisión o probar una idea?”.

Evaluación

Cómo saber si el MVP funciona

14
  1. La salida responde al problema declarado.
  2. Usa los datos entregados y no inventa evidencia.
  3. El formato permite actuar: decidir, comparar o probar.
  4. El riesgo ético está identificado.
  5. Otra persona puede repetir la prueba.
Métricas posiblesPrecisión de clasificación, satisfacción, tiempo ahorrado, calidad de recomendación y claridad de explicación.

Sin evaluación, no hay MVP: solo hay una idea entretenida.

Responsabilidad

Guardrails: ética, privacidad y sesgos

15
PrivacidadNo usar nombres reales, datos sensibles ni información personal innecesaria.
SesgoPreguntar qué grupos podrían quedar peor representados o recibir peores recomendaciones.
SupervisiónEl MVP apoya decisiones; no reemplaza el juicio humano en casos importantes.
“Antes de entregar la respuesta, revisa si estás inventando datos, usando supuestos injustos o recomendando algo que debería validar una persona responsable.”
Actividad 1

Diseñen un MVP real con IA

16
  1. Usuario objetivo: ¿quién lo usaría?
  2. Problema concreto: ¿qué dolor resuelve?
  3. Datos mínimos: ¿qué necesita recibir?
  4. Tipo de IA: recomendar, clasificar, predecir o detectar patrones.
  5. Salida esperada: ¿qué entrega al usuario?
  6. Criterio de éxito: ¿cómo sabremos si funcionó?

Regla del MVP: mientras más pequeño y comprobable, mejor. La entrega es una idea + un flujo + un prompt maestro + una forma de validación.

Actividad 2

Escriban el prompt maestro

17
Actúa como [rol]. Estamos creando un MVP para [usuario] que necesita [problema]. Usa estos datos: [datos mínimos]. Tu tarea es [acción exacta]. Entrega el resultado en [formato]. No inventes datos; si falta información, pregunta o declara supuestos. Evalúa la respuesta con [criterios]. Identifica riesgos y cómo reducirlos.
Prueba rápidaPéguenlo en una IA generativa y revisen si la salida es accionable, justa, clara y repetible.
MejoraSi sale genérico, agreguen datos de ejemplo, restricciones y una métrica de éxito.
Cierre aplicado

Pitch final: de prompt a MVP

18
Guion de 5 frases1. Nuestro usuario es...
2. Su problema es...
3. Nuestro MVP usa estos datos...
4. La IA entrega...
5. Sabremos que funciona si...
Checklist final¿Usuario claro? ¿Datos mínimos? ¿Salida útil? ¿Evaluación? ¿Resguardo ético?

Prompt engineering es diseñar instrucciones para que la IA ayude a pensar, probar y decidir con evidencia. Un MVP real no nace perfecto: nace pequeño, claro y medible.
